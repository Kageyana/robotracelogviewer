# 既存のApp Designer生成コード差で同期前の全体一致検査が停止した

## 対象と確認できた結果

MATLAB R2023bで一時MLAPP生成前に既存test.txtと既存MLAPPの実行コードを比較したところ、CRLF/LFを正規化しても全体一致しなかった。同期前のassertで停止し、元MLAPPは変更されなかった。換算処理の単体テストは通過していた。

## 原因

Python標準ライブラリでバックアップMLAPPのmatlab/document.xmlを独立に読み出して確認した。編集領域はtest.txtと完全一致し、全関数の名前も一致した。関数本体に差があるのはcreateComponentsだけで、その他はプロパティ宣言・コールバックの順序や空行だった。生成コードの全体一致を、同期前の処理内容一致の必須条件にした検証スクリプトの仮定が厳しすぎた。

## 対処

バックアップを保持し、差分を確認した後、既存編集領域がMLAPPのコードに完全一致して含まれることを同期前に検査した。test.txtをコードの正として、MATLAB FileWriterで今回専用の一時MLAPPへ保存した。生成後は全実行コードの一致、編集用コードの一致、および全UIの名前・個数・位置・Valueの保持を検査した。これらはすべて成功した。元の利用者変更は戻していない。

## 再発防止

1. 同期前に既存test.txtとMLAPPの実行コードを改行だけ正規化して比較する。
2. 不一致時は即上書きせず、XMLの独立読出しと関数単位比較で生成領域・並び順・編集処理の差を区別する。
3. 編集処理が異なる場合は差を解決するまで同期しない。生成領域だけの差の場合もUIの名前・位置・初期値を確認する。
4. 同期後の全体一致検査は緩めず、実行コード・編集用コード・デザインの保存結果を再読込して検証する。

## 確認方法

`D:/robotrace/robotrace_v2/analysis/viewer_equations_20261017/stage_and_test.m` のMATLAB実行が終了コード0。`stage-retry.log` に11正常式・21不正式、ゼロ除算・overflow・整数平均、およびMLAPP実行/編集コード同期・UI保持のPASSを記録した。今回の検証停止への対策を確認したもので、人による手動操作確認の代わりではない。
